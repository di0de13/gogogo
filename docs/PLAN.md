# LiveGrow 总体计划

## 0. 方法论与工作边界

### 0.1 总目标

在 30 天内完成一个可运行、可测试、可解释、可用于简历和面试深挖的直播营收增长平台，并形成一套 AI-native 后端开发工作流证据。

### 0.2 面试主线

候选人叙事固定为：AI/算法背景 + 主动补齐 Go 后端工程 + 面向营收场景理解分布式系统 + 用 AI 提高学习和交付效率。

### 0.3 真实性原则

- 不虚构生产经验、用户规模、QPS 或团队职责；
- 压测数据记录环境、版本、参数和日期；
- 未实现能力使用“设计”“模拟”“故障演练”而不是“线上支持”；
- AI 生成内容必须经过人工判断、测试和代码审查。

### 0.4 最低执行单元标准

一个最低单元应满足：

1. 通常可在一次交流或少数几次工具执行内完成；
2. 有明确输入、产物和验收标准；
3. 尽量只改变一个主题的状态；
4. 完成后可以独立记录，不依赖大量未完成上下文；
5. 对后续工作有可复用的接口、文档或测试。

如果一个任务同时涉及多个独立技术风险，就继续向下拆分；如果继续拆分只会产生机械性文件操作，则保持两层即可。编号是动态的，不预先强行规定所有层级。

### 0.5 每个最低单元的固定记录

- 目标；
- 前置条件；
- 执行内容；
- 产物；
- 验收结果；
- 面试可讲点；
- AI 使用与人工判断；
- 下一步。
